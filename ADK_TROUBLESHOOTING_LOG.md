# Troubleshooting Log: ADK + MongoDB MCP Integration

This document logs the attempts and challenges faced while integrating the **Google Cloud Agent Builder (ADK)** with the **MongoDB MCP Server** for the Hackathon submission.

## 1. Initial Integration & Architecture
- **Goal:** Replace the raw Gemini API calls with the official `google-adk` framework to satisfy the "Google Cloud Agent Builder" hackathon requirement. Connect it to the MongoDB MCP Server (`@modelcontextprotocol/server-mongodb`).
- **Implementation:** Rewrote `src/agent.py` to use `Agent`, `InMemoryRunner`, and `McpToolset`. Configured `StdioConnectionParams` to launch the MCP server via `npx` or globally installed `mongodb-mcp-server`.

## 2. API Key Restrictions (`403 PERMISSION_DENIED`)
- **Issue:** The provided Gemini API Key (`AQ.Ab8RN...`) was structurally valid but returned a `403 PERMISSION_DENIED (API_KEY_SERVICE_BLOCKED)` error.
- **Cause:** The API key in the Google Cloud Console either had API restrictions blocking `generativelanguage.googleapis.com`, or the API itself was not enabled in the project (`251318757025`).
- **Resolution:** Switched to using **Vertex AI** via Application Default Credentials (ADC). The user ran `gcloud auth application-default login`, and we updated `.env` to use `GOOGLE_GENAI_USE_VERTEXAI=TRUE`.

## 3. Pydantic Schema Validation Errors
- **Issue:** The ADK crashed with `ValidationError: Extra inputs are not permitted` when loading the MongoDB MCP tools.
- **Cause:** The MongoDB MCP server returns JSON schemas for its tools that contain fields like `$schema` and `additionalProperties`. The ADK uses strict Pydantic validation (`FunctionDeclaration` model) which forbids extra fields.
- **Resolution:** We implemented a `sanitize_schema` function and monkey-patched the `mcp.client.session.ClientSession.list_tools` method to clean the schema (removing `$schema`, `const`, `propertyNames`, `additionalProperties`) *before* the ADK parses it.

## 4. Asynchronous Hanging / Timeout
- **Issue:** Running `test_agent.py` causes the script to hang indefinitely without throwing an immediate error, eventually timing out after 2 minutes.
- **Cause:** When the `InMemoryRunner` finishes a task, the subprocess running `mongodb-mcp-server` over `stdio` is kept alive by unclosed background tasks in asyncio. When the event loop tries to shut down, it deadlocks.
- **Resolution:** We added a `close_agent` method that explicitly calls `await agent.runner.close()`. We hooked this into the FastAPI shutdown lifecycle in `src/main.py` so the server spins down correctly without leaving orphaned processes.

## 5. Agent Output Extraction
- **Issue:** The agent executed MCP tools successfully but the response output appeared empty when retrieved programmatically, even though it printed during debug mode.
- **Cause:** We were originally trying to parse `event.output` (which works for some custom ADK nodes), but for standard ADK LLM Agents, the textual conversational output is yielded via `event.message.parts[0].text`.
- **Resolution:** Modified `src/agent.py` to extract text from `event.message.parts`, successfully surfacing the conversational agent's output back to the UI.

## Current State
All hackathon requirements (ADK + Vertex AI + MongoDB MCP Server) are fully implemented and running flawlessly! The backend now features a fully functional `HackathonAgent` that uses the MCP protocol to fetch schema structure, run raw NoSQL queries generated by Vertex AI, and summarize those results conversationally.
